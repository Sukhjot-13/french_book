L’ÉTUDE — CURRENT UI REFINEMENT SUGGESTIONS

The current state is substantially better. Most of the major UI architecture changes are already implemented:

- Scan → Peek → Deep Dive
- dense verb/vocabulary/expression/grammar tables
- universal Peek drawer
- keyboard shortcuts
- stronger verb detail views
- chapter dashboards
- interactive examples
- compact cross-linking

At this point, do NOT do another major redesign.

The focus should now be refinement.

==================================================
1. ADD A REAL VOCABULARY DETAIL PAGE
==================================================

The data layer already supports `getVocabularyById()` with related expressions and examples, but there is no dedicated vocabulary detail route listed.

Add:

`/vocabulary/[id]`

A dictionary row should:

1. Peek first
2. Then allow full detail

The full page should show:

- canonical form
- display form
- meanings / senses
- gender
- articles
- plural
- variants
- synonyms
- antonyms
- usage notes
- related expressions
- related verbs
- examples
- related chapters
- source information

This should feel like a proper dictionary entry.

==================================================
2. IMPROVE THE HOME PAGE

The home page still sounds like a traditional dashboard with:

- counts

Avoid too many statistics cards.

Keep only a few useful counts if they help navigation.

==================================================
5. MAKE THE PEEK DRAWER CROSS-NAVIGABLE
==================================================

This is one of the strongest next improvements.

Example:

1. Peek `prendre`
2. Inside the drawer click `prendre une décision`
3. Drawer changes to the expression
4. User can go Back to `prendre`

The user should be able to explore multiple connected entities without leaving the current page.

The Peek drawer becomes a mini knowledge browser.

==================================================
10. MAKE FILTERS URL-DRIVEN CONSISTENTLY
==================================================

Use search parameters for filters wherever possible.

Examples:

`/verbs?regularity=irregular&auxiliary=avoir`

`/expressions?baseVerb=prendre`

`/examples?verb=prendre&tense=imparfait`

`/vocabulary?pos=noun&gender=feminine`

Benefits:

- filters survive refresh
- browser Back works properly
- users can bookmark useful filtered views
- cross-links can open prefiltered libraries
- sharing links becomes easy

==================================================
15. DO NOT ADD VIRTUALIZATION UNLESS NEEDED
==================================================

Current sizes are manageable:

- 496 verbs
- 1,002 vocabulary entries
- 557 expressions
- 284 grammar rules

With pagination and filtering, virtualization is probably unnecessary.

Only add it if actual performance testing shows scrolling/rendering problems.

Avoid unnecessary complexity.

==================================================

If fields such as:

- register
- frequency
- difficulty
- gender
- study metadata

are `null` or unresolved, usually do not show them.

Unknown data should generally disappear from the visual UI rather than become a badge.

Example:

Bad:
REGISTER: UNKNOWN

Better:
show no register badge

==================================================
FINAL RECOMMENDATION
==================================================

The UI architecture is now strong.

Do not keep redesigning major layouts.

Move into:

- refinement
- interaction consistency
- fast navigation
- contextual filtering
- missing-data handling
- visual polish

The application should now be evaluated page-by-page visually.

The core target remains:

SCAN quickly
→ PEEK without losing context
→ DEEP DIVE when needed
→ FOLLOW relationships naturally
→ RETURN without losing browsing state

Once these refinements are implemented, further improvements should be driven mainly by actual usage and visual testing rather than adding more architectural features.
