GEMINI BOOK-PARSING TODO
Practice Makes Perfect: Complete French Grammar
Agent execution checklist for a Next.js/TypeScript project
===========================================================

PURPOSE
-------
This file is the operational TODO for the AI agent that will parse the full French grammar book into
the structured revision dataset defined by:

    docs/french_revision_super_dataset_spec.txt

The specification file is the AUTHORITATIVE DATA CONTRACT.
This TODO is the AUTHORITATIVE EXECUTION PLAN.

The goal is NOT merely to "extract some JSON."
The goal is to finish the entire parsing pipeline so that, when every acceptance check in this file passes:

    1. every chapter has been parsed,
    2. all important grammar, vocabulary, verbs, conjugations, expressions, collocations,
       constructions, examples, and exercises have been captured,
    3. all back matter has been reconciled,
    4. all duplicate entities have been canonicalized,
    5. all cross-links resolve,
    6. provenance is preserved,
    7. validation passes,
    8. coverage is verified,
    9. the final dataset is ready for the revision app.

DO NOT MARK THIS PROJECT "PARSING COMPLETE" UNTIL THE FINAL ACCEPTANCE GATE PASSES.

===========================================================
0. NON-NEGOTIABLE RULES
===========================================================

[ ] Read docs/french_revision_super_dataset_spec.txt completely before writing extraction code.
[ ] Treat that specification as the schema contract.
[ ] Locate the source French grammar PDF in docs/ and record the exact path.
[ ] Do not invent source-derived facts.
[ ] Do not silently add outside French knowledge and label it as book content.
[ ] Any deliberate extra learner-friendly content must use source_type = "study_extension".
[ ] Any normalized structure inferred from multiple book examples must use source_type = "derived_from_book"
    where appropriate.
[ ] Preserve French accents, apostrophes, hyphens, gender, articles, and spelling in display text.
[ ] Keep search-normalized forms separate from display forms.
[ ] Chapters are source/navigation metadata, NOT the primary storage hierarchy.
[ ] Global canonical collections are required.
[ ] Never create a second canonical verb just because the same verb appears in another chapter.
[ ] Never create a second canonical vocabulary item merely because it is repeated.
[ ] Repeated occurrences become attestations.
[ ] Every relation ID in the final data must resolve.
[ ] Never skip a section because it appears "easy" or "unimportant".
[ ] Do not extract only headings or vocabulary boxes; inspect examples and exercises for reusable language.
[ ] Explicitly capture high-value constructions and collocations.
[ ] Examples include:
        venir chercher quelqu'un
        demander à quelqu'un de + infinitif
        prendre une décision
        prendre la décision de + infinitif
        avoir besoin de
        je pense que
    when supported by the source or clearly marked as a study extension.
[ ] Conjugations must link to BOTH a canonical verb and canonical tense/mood entity.
[ ] Validate after every chapter/batch, not only at the end.
[ ] Keep intermediate files; do not overwrite all history with one opaque final generation.
[ ] Use deterministic IDs according to the specification.
[ ] Generate machine-readable QA reports.
[ ] Do not claim parsing is complete when unresolved low-confidence data or broken references remain,
    unless explicitly documented as unavoidable and approved.
