## 🟢 Improvements

- **2026-09-28**: (Implemented) Fixed four guaranteed hydration-mismatch / impure-render defects. (1) `PronunciationButton` no longer returns `null` from its render body when `window` is undefined, which made the server emit no button and the first client render emit one on every `/verbs/[id]` and `/vocabulary/[id]`; the button now always renders, support is detected via `useSyncExternalStore`, the handler no-ops when unsupported, and the control stays visible with `aria-disabled`. (2) `ReviewSession` no longer calls `getDueCards()` inside a `useState` initializer, so the server no longer treats every card as due while the client treats a filtered subset as due; the SRS store is now read exclusively through `useSyncExternalStore` and the queue/stats are memoized. (3) `PeekContext.openPeek` now clears `peekData` before awaiting and guards writes with a monotonic request counter, so a 404 can no longer leave the previous entity's title and facts in the drawer and two fast peeks cannot resolve out of order. (4) `PeekTrigger`'s inline variant is a real `<button type="button">` instead of a `span` with no role, `tabIndex` or key handler that called `preventDefault()` and could hijack an enclosing `Link`; the `PeekDrawer` backdrop is a real button, so it is keyboard reachable.
- **2026-09-28**: (Implemented) Fixed vocabulary identity end to end. `makeVocabId` no longer strips leading articles, the four `rawId.startsWith(...)` prefix clauses were removed from `getVocabularyById`, and a single memoized `getVocabIndex()` now assigns the deduplicated id once for the table, the detail page, search results and the review-store key. Measured against `data/MASTER_DATA.json`: **188 → 0** ids resolving to the wrong record (the audit's headline figure of 14 counted only the article-collision subset; prefix matching broke 188), **13 → 1** colliding base-id groups (the residual `Toile` / `toile` pair is case-only and is disambiguated by the chapter suffix, with both ids resolving to themselves), and 20 → 6 mis-resolving canonical-form URLs (the residual 6 are genuine same-word-different-POS records). All vocabulary links, peeks and review keys now use the canonical id.
- **2026-09-28**: (Implemented) Hardened both API routes. `/api/search` clamps `limit` to 1–50 (default 20; previously unbounded and returning ~2500 results / ~600 KB per request after a full 18 MB scan), rejects a non-numeric `limit` with `400` instead of `slice(0, NaN)`, rejects a `q` longer than 100 characters with `400`, and sets `Cache-Control: public, max-age=60, s-maxage=300, stale-while-revalidate=600` on every response. `/api/peek` decodes the id once through a guarded `safeDecode` helper and returns `400` for a malformed value such as a trailing `%`, instead of turning the `URIError` into a `500`; vocabulary peek payloads now return the canonical id and `/vocabulary/<id>` URL.
- **2026-09-28**: (Implemented) Fixed per-render `localStorage` thrash. `RowActionMenu` previously called `isItemSaved` and `isItemReviewed` during render, so a 50-row page (mobile list *and* desktop table both mounted) performed roughly 200 full reads and parses per render pass plus 100 `window` listeners, and neither key map was ever pruned. The flags are now hydrated once per menu in a mount effect from a new `getReviewStateSnapshot()` that reads both maps in one pass and prunes non-boolean keys, and `VocabDictionaryTable` renders only the active breakpoint via a new `useIsDesktop()` `matchMedia` hook, halving the mounted menus from 100 to 50.
- **2026-09-28**: (Implemented) Fixed NaN pagination on all seven filterable list routes. `parseInt` on a non-numeric, zero, negative or oversized `?page=` produced a `NaN` offset, so the slice was empty while the header reported the full entry count and "Page NaN of NaN". A shared `src/lib/pagination.ts` (`parsePageParam`, `paginate`) now defaults, clamps and floors `totalPages` at 1; every table also floors its own `totalPages`.
- **2026-09-28**: (Implemented) Added the missing route boundaries: `app/not-found.tsx` (the seven detail routes all called `notFound()` but rendered Next's unstyled default outside the app shell), a client `app/error.tsx` with a `reset()` action (any selector throw previously white-screened the app), and `loading.tsx` skeletons for the twelve list and detail routes via a shared `ListSkeleton`.
- **2026-09-28**: (Implemented) Added static generation for the fully static 18 MB dataset. `generateStaticParams` was added to all seven dynamic id routes via `src/lib/data/staticParams.ts`, taking the build from 18 prerendered pages to **2614**; the route table now shows `●  (SSG)` for `/chapters/[id]`, `/concepts/[id]`, `/expressions/[id]`, `/grammar/[id]`, `/tenses/[id]`, `/verbs/[id]` and `/vocabulary/[id]`. The seven filterable list routes intentionally stay `ƒ` because they read `searchParams`; `dynamic = "force-static"` was tried on `/traps` and verified to serve byte-identical HTML for `/traps` and `/traps?query=avoir`, i.e. it silently breaks filtering, so it was reverted.
- **2026-09-28**: (Implemented) Fixed three prerender crashes caused by the dataset violating its own declared TypeScript shapes, all of which were latent because the detail routes were previously rendered per request: `expressions.complement_structure` is an object in **all 557** records but was typed `string | null` and rendered directly (now flattened by `formatComplementStructure`); `vocabulary.word_family` mixes bare strings with `{ canonical_form, part_of_speech }` references and `vocabulary.variants` are `{ form, variant_type, note }` objects (now flattened by `formatVocabRelations`); and `vocabulary.senses` use an `english` key with nested `articles` while the UI contract read `english_gloss` (now normalized by `normalizeVocabSenses`). The lesson is recorded in the architecture doc: the dataset, not the type declarations, is the source of truth.
