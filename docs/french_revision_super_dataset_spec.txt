FRENCH REVISION SUPER DATASET
Complete Data Model + Extraction Rules + HTML/Revision App Instructions
=======================================================================

SOURCE BASIS
------------
Primary source book:
Practice Makes Perfect: Complete French Grammar
Author: Annie Heminway

This specification is designed for a full-book extraction into a reusable JSON study database.
The dataset must NOT be chapter-only. Chapters remain important as source/browsing metadata,
but the main study collections are GLOBAL: verbs, conjugations, tenses, grammar rules,
vocabulary, expressions/constructions/collocations, examples, exercises, concepts, and study sets.

The source book itself explains that vocabulary can appear inside exercises or highlighted boxes,
and that glossaries and verb charts are useful review/reference resources. Therefore extraction
must inspect ALL sections, exercises, vocabulary boxes, verb tables, glossaries, and answer keys,
not only obvious headings.

=======================================================================
0. FINAL ARCHITECTURE DECISION
=======================================================================

Use a graph-like linked dataset, not a deeply nested chapter tree.

GOOD:
- one canonical verb object for "venir"
- one canonical expression object for "venir chercher quelqu'un"
- one canonical tense object for "présent de l'indicatif"
- one conjugation object linking "venir" + "present"
- all objects linked by stable IDs
- every book occurrence recorded as an attestation/source reference
- chapter only stores IDs of items appearing in it

BAD:
chapter -> full duplicate verb -> duplicate expressions -> duplicate conjugations

The same item must be reusable from multiple views:
- Verb view
- Expression view
- Tense view
- Grammar view
- Vocabulary view
- Concept view
- Chapter view
- Exercise view
- Revision/filter view

Example:
"venir chercher quelqu'un"
must appear:
- under the verb "venir"
- under the verb "chercher"
- under Expressions
- under Collocations/Verb Patterns as appropriate
- under Daily Life / Movement / Picking someone up
- in Essential items if priority is high
- under its source chapter(s)
- in examples/exercises that use it

=======================================================================
1. DESIGN GOALS
=======================================================================

The dataset must support all of the following:

1. Browse by chapter.
2. Browse all vocabulary globally.
3. Browse all verbs globally.
4. Browse all expressions globally.
5. Browse all tenses globally.
6. Browse all grammar rules globally.
7. Browse all examples globally.
8. Browse all exercises globally.
9. Filter by learning priority.
10. Filter by usefulness.
11. Filter by difficulty.
12. Filter by CEFR if later assigned.
13. Filter by register: formal / neutral / informal / colloquial / literary.
14. Filter by spoken/written usage.
15. Filter by topic: time, travel, food, work, opinion, movement, etc.
16. Filter by grammatical concept: negation, object pronouns, agreement, questions, etc.
17. Find every expression related to a selected verb.
18. Find every conjugation related to a selected verb.
19. Find every verb/conjugation related to a selected tense.
20. Find every grammar rule related to a selected tense.
21. Find collocations such as "prendre une décision".
22. Find productive verb patterns such as "demander à quelqu'un de + infinitif".
23. Find sentence starters such as "je pense que".
24. Find fixed expressions such as "avoir besoin de".
25. Find conversation phrases such as "ça marche".
26. Find connectors such as "par contre".
27. Track all occurrences of an item in the book.
28. Keep book-derived content separate from study extensions.
29. Keep learner progress separate from reference content.
30. Support future flashcards, cloze drills, verb drills, pattern drills, and spaced repetition.
31. Support accent-insensitive and alias-aware search.
32. Support cross-links without duplicating content.
33. Remain splittable into multiple JSON files later without changing IDs or relationships.
34. Be auditable: every book-derived item should have source/attestation information.
35. Be quality-controlled: parsing uncertainty must be trackable.

- favorite
- status
- times_seen

Recommended implementation:
- french_grammar.json = layers A + B

Never rewrite the master content dataset every time the learner answers a quiz.

4. GLOBAL ID CONVENTIONS
=======================================================================

Every reusable entity must have a stable unique ID.

Recommended prefixes:

book_        book
chapter_     chapter
section_     section
concept_     grammar/semantic concept
tense_       tense or mood/form
rule_        grammar rule
verb_        verb
conj_        conjugation
expr_        expression / construction / collocation / idiom
vocab_       vocabulary item
example_     example sentence
exercise_    exercise
studyset_    study set

Examples:
verb_venir
verb_demander
expr_venir_chercher_qqn
expr_demander_a_qqn_de_inf
expr_prendre_une_decision
tense_present_indicative
tense_passe_compose
rule_ne_pas
concept_negation
vocab_decision
example_demander_001

ID rules:
1. lowercase ASCII only
2. spaces -> underscore
3. remove accents only in IDs, NOT in French display text
4. stable once published
5. never reuse an old ID for a different entity
6. aliases belong in "aliases", not by changing the ID

=======================================================================
6. SOURCE / ORIGIN / PROVENANCE
=======================================================================

Allowed source_type values:

"book"
    Directly supported by the uploaded book.

"derived_from_book"
    A normalized/combined item derived from multiple book examples or occurrences,
    without adding an outside linguistic claim.

"study_extension"
    Useful material intentionally added beyond what is explicitly taught in the book.
    Example: an extra high-value sentence starter or collocation.

"external_reference"
    Reserved for later enrichment from an outside dictionary, corpus, CEFR list, etc.

Every non-book addition MUST be marked.
Never silently make outside knowledge look like book content.

Attestation object:

{
  "source_type": "book",
  "chapter_number": 4,
  "chapter_id": "chapter_04",
  "section_id": "section_04_venir",
  "page_printed": 36,
  "page_pdf": null,
  "context_type": "grammar_explanation",
  "exercise_id": null,
  "source_anchor": null,
  "notes": null
}

context_type examples:
- chapter_title
- grammar_explanation
- conjugation_table
- vocabulary_box
- expression_list
- example_sentence
- exercise_instruction
- exercise_question
- answer_key
- verb_table
- glossary_fr_en
- glossary_en_fr

Do not store long copied source passages merely for audit.
Page/section/source anchor is usually enough.

=======================================================================
7. IMPORTANCE, USEFULNESS, DIFFICULTY, AND FREQUENCY
=======================================================================

These concepts MUST stay separate.

study.learning_priority:
1 = low priority / specialized / rare for revision
2 = occasional usefulness
3 = useful
4 = very useful
5 = essential / high-value / highly reusable

study.usefulness:
1 = narrow use
2 = limited
3 = useful
4 = broadly useful
5 = extremely useful in real communication/revision

study.difficulty:
1 = very easy
2 = easy
3 = intermediate
4 = difficult
5 = advanced / subtle

frequency:
{
  "book_occurrences": 0,
  "book_frequency_tier": "rare|occasional|common|very_common|null",
  "real_world_frequency": null,
  "real_world_frequency_source": null
}

IMPORTANT:
- "book_occurrences" is an objective count from attestations.
- "learning_priority" is a learner-oriented editorial rating.
- "real_world_frequency" must remain null unless reliable outside frequency data is intentionally added.
- Do not pretend learner priority is corpus frequency.

=======================================================================
18. EXPRESSIONS — CORE DESIGN
=======================================================================

Expressions are a major study collection, not a miscellaneous list.

Allowed expression_type:

1. verb_pattern
   demander à quelqu'un de + infinitif

2. collocation
   prendre une décision

3. fixed_expression
   avoir besoin de

4. idiom
   idiomatic meaning not fully predictable from the words

5. sentence_starter
   je pense que

6. conversation_phrase
   ça marche

7. connector
   par contre

8. functional_phrase
   à mon avis / en ce qui concerne...

9. formulaic_phrase
   fixed social or discourse formula

All can be revised collectively.

29. DUPLICATES / CANONICALIZATION
=======================================================================

Critical rule:
One canonical item, many attestations.

Create:

Then:
"attestations": [15 source references]

Vocabulary:
normalized canonical_form + part_of_speech + sense distinction

Verb:
infinitive

Expression:
normalized canonical_form + expression_type

Grammar rule:
semantic rule identity, not title alone

Example:

Exercise:

=======================================================================
39. EXTRACTION RULES — FULL BOOK
=======================================================================

The extraction process must follow these rules:

1. Read every chapter.
2. Read every section.
3. Read every vocabulary box.
4. Read every verb list.
5. Read every conjugation table.
6. Read every example sentence.
7. Read every exercise.
8. Read the answer key.
9. Read verb tables.
10. Read both glossaries.
11. Vocabulary inside exercises must be considered.
12. Expressions inside examples/exercises must be considered.
13. Repeated items must merge into canonical entities.
14. Every occurrence becomes an attestation.
15. Do not rely on chapter headings alone.
16. Do not assume a word is unimportant because it appears only once.
17. Do not assume a repeated word is high real-world frequency.
18. Keep source meaning/terminology faithful to the book.
19. Do not silently correct or expand the book using outside knowledge.
20. If useful study extensions are added, mark them "study_extension".
21. If PDF text extraction is unclear, inspect the page image before deciding.
22. Broken ligatures/OCR-like parse artifacts must be normalized cautiously.
23. French accents must be preserved.
24. Glossary entries may be used to reconcile canonical forms/translations.
25. Verb tables may be used to complete conjugation objects that the chapters reference.
26. Answers from the answer key must link back to exercise question IDs.
27. If an answer is open-ended, preserve that fact rather than inventing one definitive answer.
28. If a pattern can be extracted from multiple examples, mark "derived_from_book" if the book does not explicitly state the pattern.
29. Store literal book examples separately from model-generated examples.
30. Generated examples, if any, must be "study_extension".

=======================================================================

=======================================================================

During extraction, actively detect and preserve:

A. Verb + preposition patterns
- penser à
- essayer de
- réussir à
- etc.

B. Verb + person + infinitive patterns
- demander à quelqu'un de + infinitif
- dire à quelqu'un de + infinitif

C. Verb + noun collocations
- prendre une décision
- poser une question
- faire attention

D. Multi-verb combinations
- venir chercher quelqu'un
- aller voir quelqu'un

E. Fixed expressions
- avoir besoin de
- avoir envie de

F. Sentence starters
- je pense que
- à mon avis

G. Connectors / discourse markers
- par contre
- cependant
- donc
- etc. if present/supported

H. Conversation phrases
- high-value spoken formulas if present or intentionally added as study extensions

These are not "just examples".
They are reusable learning units.

43. VALIDATION RULES
=======================================================================

Before considering the dataset complete:

1. All IDs unique.
2. All relation IDs resolve to existing entities.
3. All chapters use valid chapter numbers.
4. All source pages are plausible.
5. All book-derived items have at least one attestation.
6. All study_extension items are clearly marked.
7. No accidental duplicate canonical verbs.
8. No accidental duplicate vocabulary lexemes/senses.
9. No accidental duplicate expressions.
10. Conjugation verb_id exists.
11. Conjugation tense_id exists.
12. Exercise answers map to existing questions.
13. Every noun gender uses allowed values:
    masculine / feminine / common / variable / unknown / null
14. Every register uses taxonomy values.
15. Every expression_type uses taxonomy values.
16. Every priority/usefulness/difficulty is 1–5 or null.
17. French display text preserves accents.
18. Search-normalized text may remove accents but display text must not.
19. No orphan examples unless intentionally standalone.
20. Every chapter/section relation should be internally consistent.
21. attestation count should equal frequency.book_occurrences for book occurrences.
22. Study sets must not reference nonexistent IDs.
23. No source-derived claim should be falsely labeled as editorial or vice versa.

45. HTML APP — BUILD REVERSE INDEXES
=======================================================================

Do not duplicate every relationship in JSON if it can be derived.

Example:

const expressionsByVerb = new Map();

for (const expression of data.expressions) {
  for (const verbId of expression.base_verb_ids || []) {
    if (!expressionsByVerb.has(verbId)) {
      expressionsByVerb.set(verbId, []);
    }
    expressionsByVerb.get(verbId).push(expression.id);
  }
}

Similarly build:

- examplesByExpression
- examplesByTense
- exercisesByVerb
- exercisesByTense
- rulesByTense
- vocabularyByChapter
- expressionsByChapter
- etc.

70. FINAL RULES TO FREEZE BEFORE EXTRACTION
=======================================================================

1. Chapter is a source/navigation dimension, not the dataset hierarchy.
2. Everything important gets a global canonical entity.
3. Repeated occurrences become attestations, not duplicates.
4. Verbs, conjugations, expressions, tenses, and rules are linked by IDs.
5. High-value constructions are first-class expressions.
6. "prendre une décision" is a collocation, not merely an example.
7. "demander à quelqu'un de + infinitif" is a productive verb pattern.
8. "venir chercher quelqu'un" links to both "venir" and "chercher".
9. "je pense que" is a sentence-starter/function expression.
10. Conjugations are separate objects so both Verb -> Tenses and Tense -> Verbs are easy.
11. Vocabulary is global and nouns preserve article/gender.
12. Examples are reusable first-class objects.
13. Exercises are linked to the exact concepts/verbs/tenses they test.
14. Book frequency and learner priority are separate.
15. Real-world frequency remains null until intentionally sourced.
16. Book-derived and study-extension content are clearly separated.
17. User progress is stored separately from reference content.
18. Search is accent-insensitive but display text preserves correct French.
19. Quality/confidence metadata is mandatory for a large automated extraction.
20. Validate every relation and ID before publishing the dataset.

73. DATASET PHILOSOPHY
=======================================================================

The goal is NOT to create a digital copy that is only browsed chapter by chapter.

The goal is to create a connected French revision knowledge base where:
- a verb leads to all its forms and constructions
- a tense leads to all its rules and conjugations
- a word leads to its collocations
- an expression leads to its base verbs and patterns
- a grammar rule leads to examples and exercises
- a chapter remains available as the source map
- revision can surface the most valuable material first

The dataset should answer questions such as:

"What are the most important expressions using prendre?"
"What collocations use décision?"
"Show me every verb pattern with de + infinitive."
"Show me all expressions related to venir."
"Show me all conjugations of venir."
"Show me all important irregular verbs in the passé composé."
"Show me every rule related to negation."
"Show me all high-priority vocabulary from the whole book."
"Show me only sentence starters for giving opinions."
"Show me my weak expressions."
"Show me all items from Chapter 4."
"Show me every place the book uses this expression."

If the JSON can support all of those without duplicating content, the architecture is correct.
